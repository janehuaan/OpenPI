# OpenPI Personal Agent OS 架构设计与生产级规范 (v1.1)

> **核心愿景**：将 OpenPI 从被动等待指令的 Coding Agent，进化为懂用户、长记忆、主动办事、具备确定性安全防线与物理资源约束的 **Personal Agent 操作系统**（对标并超越 Muse / Cue / Today 交互范式）。

---

## 0. 核心定位与根本原则

### 0.1 核心定位
OpenPI 不应该做成一个“功能更多的 Chat 界面”，也不应该重构成通用聊天玩具。
* **底座定位**：OpenPI 拥有业界极其强大的代码执行底座（Execution Core）：原生受控终端、文件局部精准修改、工作流编排、多 Agent 协作、代码 AST 检索与双盲质检。这是 OpenPI 的立足之本（**HOW**）。
* **进阶定位**：引入个人智能层（Personal Intelligence Layer），赋予 Agent 长期理解、身份认知、目标规划、主动意图与严谨自律能力（**WHY / WHAT / WHEN**）。

### 0.2 第一设计原则（架构铁律）
> **严格冻结 Execution Core，HOW 与 WHY/WHAT/WHEN 彻底解耦。**

* **Execution Core（openpi-engine 与 openpi-tools）零污染**：执行核心只负责专注高效地完成具体工程指令，不需要知道用户的终身画像与宏大目标。
* **穿透统一执行网关（Execution Gateway）**：个人智能层与执行核心之间必须通过受控网关进行通信，网关强制执行权限检查、预算预扣、超时注入与熔断监控。

## 2. 个人智能中枢设计 (Personal Intelligence)

### 2.1 7 维生命周期记忆模型
彻底摒弃单一向量数据库的粗暴方案，将记忆划分为 7 个离散维度，并应用艾宾浩斯动态半衰期衰减：

| 分类 | 语义范围 | 默认半衰期 | 衰减策略 |
| :--- | :--- | :--- | :--- |
| **Profile** | 用户的核心身份、角色、设备、常用环境 | 60 天 | 极长保留，稳定更新 |
| **Preference** | 编码规范、设计偏好、工具使用习惯 | 30 天 | 访问自适应抗衰减强化 |
| **Project** | 特定项目的架构决策、依赖选型、约定 | 14 天 | 关联项目活跃度 |
| **Decision** | 关键技术论证、架构方案选型结果 | 45 天 | 永久保留高置信决策 |
| **Experience** | 踩坑反思、Bug 纠错教训 | 30 天 | 错误重复时动态提升权重 |
| **Feedback** | 用户对 Agent 本身的评价与显式纠正 | 7 天 | 转化为经验后平滑归档 |
| **Temporary** | 当日上下文、待办暂存 | 1 天 | 24 小时后自然过期 |

* **1500 Tokens 硬顶动态上下文切片器 (`context_builder.rs`)**：
  在主回复生成前，动态检索并打分候选记忆，按预算上限 1500 tokens 格式化切片注入 `[OpenPI Personal Memory Context]`，彻底防止 Prompt 无节制膨胀与成本失控。

### 2.2 长程目标状态机 (`goal.rs`)
* 状态拓扑：`Draft` $\to$ `Active` $\rightleftharpoons$ `Blocked` / `Waiting` $\to$ `Completed` / `Cancelled` $\to$ `Archived`。
* 进度管理：`0.0 ~ 1.0` 连续标尺；当进度达到 `1.0` 时自动结项，跨越会话持续推动主线演进。

### 2.3 主动服务与晨报引擎 (`proactive.rs`)
* 每天早晨或冷启动时，自动汇总：
  1. **时段智能问候**：根据时间与用户昵称个性化生成；
  2. **主线聚焦 (Daily Focus)**：当前最重要的 Active 目标与下一步具体行动；
  3. **建议行动卡片 (Action Cards)**：低打扰卡片（代码质量扫描、Memory 维护、计划排期），支持一键点击即执行。

## 3. v1.1 工业级生产防线 (openpi-safety)

### 3.1 故障模型与熔断器 (`circuit_breaker.rs`)
建立严密的状态转移机制，杜绝 Agent 因连续异常失控消耗系统资源：
```text
           [3次连续失败]              [30s 冷却结束]
  HEALTHY ─────────────► DEGRADED ─────────────────► CIRCUIT_OPEN
     ▲                                                    │
     │                 [探针成功 2/2]                     │
     └─────────────────────────────────── RECOVERY ◄──────┘
                       [探针失败 1次]        │
                             └───────────────┘
```
* **ExecutionConstraint 物理硬预算包**：
  * 单步超时 $\le 60\text{s}$，流水线超时 $\le 600\text{s}$；
  * 内存硬红线 $\le 512\text{MB}$（超限进程级隔离释放）；
  * 重试预算上限 $\le 2$ 次（指数退避）；
  * 单轮工具调用限额 $\le 15$ 次；
  * 子 Agent 递归调用深度 $\le 2$；
  * 全局 Kill Switch 强停通道（秒级释放全部子任务）。

### 3.2 分层资源预算管理器 (`budget.rs`)
* **30% vs 70% 配额拓扑**：
  * **30% Personal Agent 配额**：供感知、记忆索引、离散决策与主动晨报使用；
  * **70% Execution Core 配额**：供 Agent 主循环、子工具执行、多步工作流消耗。
* **五步严谨闭环**：
  $$\text{Reserve (预扣)} \longrightarrow \text{Execute (执行)} \longrightarrow \text{Meter (遥测核销)} \longrightarrow \text{Release (未耗释放)} \longrightarrow \text{Report (入账审计)}$$
* 当资源使用率 $\ge 85\%$ 时，触发告警并强制降级行动（仅观察、不主动调用昂贵大模型）。

### 3.3 离散可测决策矩阵 (`decision.rs`)
彻底废弃连续浮点数乘积，改用工程可单测的 0~3 标度离散等级与有限确定性规则集：
* **输入维度**：`Importance (0~3)`, `GoalRelevance (0~3)`, `Confidence (0~3)`, `Risk (0~3)`, `ExpectedValue (0~3)`, `InterruptionCost (0~3)`, `ActionCost (0~3)`, `HasPermission (bool)`。
* **有限动作输出**：
  `IGNORE`（静默忽略）、`REMEMBER`（记入经验）、`SUGGEST`（低打扰卡片提示）、`ASK`（征求用户确认）、`PREPARE`（就绪准备）、`EXECUTE`（自主执行）、`RESUME`（恢复执行）、`MONITOR`（持续观察）。
* 保证所有决策分支均具备确定性单元测试覆盖。

### 3.4 学习防污染与归因回滚层 (`attribution.rs`)
* **归因分流三叉戟**：
  * `PreferenceChange`：用户行为模式改变 $\to$ 形成候选偏好 $\to$ 证据链沉淀；
  * `RequirementChange`：临时项目需求变动 $\to$ 仅作用于当前项目/会话，绝不污染全局偏好；
  * `BugOrError`：结果缺陷 $\to$ 转化为反思与踩坑教训 (Experience)。
* **版本化溯源与原子回滚**：
  * 偏好记录携带唯一 ID、版本号、置信度与证据链（`evidence[]`）；
  * 提供 `rollback_preference(id)` API，保证“Agent 学错了随时能够撤回”。

## 4. 十大系统不变量 (System Invariants)

在任何异常条件或复杂递归下，系统绝对不可逾越的 10 条底线：
1. **可终止路径**：任何执行都有明确的硬超时与外部强停机制。
2. **权限边界约束**：自主行动必须具备只读或受限权限，高危破坏性操作严禁越权。
3. **长期学习可溯源**：所有持久化偏好都必须持有具体会话或提交的证据链。
4. **模型更新可回滚**：所有沉淀偏好与画像更新均具备原子回滚能力。
5. **物理资源刚性封顶**：任何后台感知与常驻任务都受 CPU/内存/Token 硬预算约束。
6. **事件洪峰去抖隔离**：高频文件与终端变更必须经过防抖聚合，严禁无限放大为 LLM 交互。
7. **不可绕过网关**：个人智能层对底层工具与代码的调用必须且只能穿透统一 Execution Gateway。
8. **核心失败状态隔离**：代码执行崩溃或语法错误绝不能破坏个人目标与画像树。
9. **错误决策防递归**：决策动作产生的衍生事件递归深度严格限定 $\le 1$。
10. **熔断降级自保**：当熔断器击穿为 Open 状态时，系统无条件降级至“只观察、不行动”。

## 5. 沉浸式 OS 桌面工作台交互实现

* **顶部全局导航**：Mac 三色原点、统一搜索条（回车提问、搜记忆、搜项目）、个人设置。
* **主屏 Hero**：暮光自然风光 Banner、时段动态问候、当前主线目标进度卡片（72% 进度条，一键推进）。
* **核心指标流**：待办目标、进行中任务、已完成里程碑、安全状态指示灯。
* **右侧 Agent HUD**：
  * 实时工作状态、当前目标、下一步行动；
  * 熔断器状态徽章 (`Healthy` / `Degraded` / `Open`)；
  * 分层资源预算监控（Personal 30% / Core 70% 用量及水位线）；
  * 相关偏好芯片（支持点击溯源与回滚）。
